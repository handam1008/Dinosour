2026-09-18 빠른 이동·발사 검증

지연 급변 뒤 입력이 계속 쌓이는 문제, 물약 종류가 바뀌는 순간의 잘못된 발사, 이동 중 물약 명중 누락, 지형 접촉 후 투사체 역행을 수정했다. 추가 검사에서 둔화·가속 수신 때 화면 위치가 튀는 문제도 재현해 수정했다.

수정 내용

- 서버가 받지 않은 다음 이동 입력을 임의로 진행하지 않는다. 중복 전송 범위를 벗어난 누락만 대체하고, 보관한 시간 안에서 한 물리 단계당 최대 두 입력을 처리해 지연이 줄었을 때 대기열도 회복한다. 상대 표시의 중복 40ms 지연도 제거했다.
- 마녀 물약은 서버가 발급한 재고 ID로 요청한다. 교체 직전에 던진 물약은 1.25초 안에서 당시 종류로 한 번만 소비한다. 이 보관 시간은 순간 RTT와 분리해 지연 급증에도 갑자기 짧아지지 않는다. 예약 슬롯 직접 사용·재사용·만료·이전 라운드 요청은 거절한다.
- 물약의 실제 캡슐 크기와 상대 위치 이력을 사용해 충돌을 판정한다. 직접 명중과 범위 피해의 중복, 자가 회복, 반사 종료 조건을 확인했다.
- 지형이 이동·비활성화·삭제되면 접촉 표시를 해제한다. 서버의 아직 접촉점에 도달하지 않은 위치를 탈출로 오해하던 조건과 해제 직후 역행을 수정했다.
- 서버 속도 효과를 적용할 때 몸체는 즉시 보정하고 화면은 이전에 표시한 월드 좌표에서 이어진다. 보정이 이동 반대 방향이면 해당 프레임의 실제 표시 이동량을 기준으로 제한한다. 마술사 카드의 선행 표시는 화면상의 캐릭터에서 시작하며, 서버 발사 원점은 검증된 몸체 위치를 유지한다.
- 프로토콜과 방 검색 버전은 4다. 두 플레이어 모두 같은 최신 빌드를 사용해야 한다.

검증 범위와 실패 분석

같은 Windows PC의 두 프로세스, 30/60/144 FPS, 인위적 송신 지연·변동·손실, 실제 UGS Relay를 사용했다. 서로 다른 두 PC의 장시간 실전은 아직 검증하지 않았다. 현재 인터넷 경로에 ProtonVPN이 있으며 측정 RTT 전체가 VPN 때문이라고 확정하지 않는다. 실제 통신 시간을 0으로 만들거나 모든 네트워크 상태에서 지연이 없다고 보장하지 않는다.

SprintTurns03의 1.61유닛 보정은 컴퓨터 부하가 아니라 물약 속도 효과 수신 때문이었다. 두 보정 순간의 클라이언트 프레임은 약 6.94ms였다. EffectsBefore01은 접속자 Side=-1을 검사 입력에서 반영하지 않은 잘못된 재현이며 성공 수에 포함하지 않는다. EffectsBefore02에서 방향을 고친 뒤 큰 역행을 재현했다. Relay/Sprint02·03은 생성 대기 45초를 넘겨 실패했으며, 단계 기록과 120초 제한을 사용한 Sprint04는 약 39초에 생성됐다. 영구 교착이나 프로토콜 불일치로 판단하지 않았다. BurstAfter01은 두 발이 동시에 살아 있어야 하는 검사에서 투척 방향 때문에 실패했고, 수직 투척과 충분한 체력 조건으로 BurstAfter02를 확인했다.

SprintTurns06에서는 마녀 action7의 실제 선행 발사가 약 0.996초 뒤 거절됐다. 빈손 검사 오류가 아니며, 쿨다운·라운드 변경·프레임 정체는 배제했다. 교체 당시 RTT로 정한 재고 만료가 가장 유력하지만, 당시 서버 재고 ID·만료시각을 기록하지 않아 분기값까지 직접 확정하지는 못했다. 같은 코드의 SprintTurns08은 거절 0이므로 간헐적 사례다. 보관시간을 기존 상한 1.25초로 고정하고 1.1초 뒤 소비·같은 ID 재사용 거절 검사를 추가했다. 이후 SprintTurns09·10과 StockAfter02에서 각각 17·16·8발이 거절 없이 승인됐다. 1.25초를 초과한 요청까지 무제한 승인하지는 않는다.

StockBefore02의 입력 직전 재고 표본은 최대 약 100ms 간격이다. 수정 후에는 실제 선행 표시의 ShotKind를 계측해 서버 종류와 비교했다.

StockChecks.cs·ContactChecks.cs·ViewChecks.cs는 Unity CLI eval용 검사다. Combat.py의 turns/effects/stock/burst/self/impact와 기존 Verify.ps1, Flight.ps1 + Trajectory.py, Special.ps1 + Specials.py, Relay.ps1으로 재실행한다. Sprint.json에는 빌드 식별자와 소스·원본 기록의 SHA-256을 남긴다. 원본은 프로젝트 Logs 아래에 보관한다.
