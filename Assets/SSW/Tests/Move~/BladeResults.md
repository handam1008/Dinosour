# 경사 점프와 칼 순간이동

2026-09-26. Base ef7a9e3에서 작업. Unity 6000.5.2f1, Unity CLI 사용.

## 수정

- 실제 CapsuleCollider2D로 이동·접촉을 검사하고, 시작부터 닿아 있는 경우 실제 접촉 법선을 사용한다. 경사각에 맞는 여유 거리를 유지한다.
- 경사 겹침 복구가 상승 속도를 만들어 점프 입력을 버리던 문제를 수정했다. 실제 점프·이동 발판 속도·대시는 유지한다.
- 암살자는 칼의 물리 좌표를 목적지로 사용한다. 플레이어에서 칼까지 가로·세로로 이동시키던 경로 제한을 제거했다.
- 바닥·벽·경사는 접촉 법선과 플레이어 크기에 맞춰 같은 면의 빈 공간에 배치한다. 캐릭터가 들어갈 수 없는 틈은 거부한다.
- 공중 회수 입력에는 누른 순간 보이던 자기 칼의 action과 위치를 담는다. 서버는 같은 소유자·칼인지 확인하고 실제 비행선에 투영한다. 보정은 RTT 기반 범위와 최대 350ms로 제한하고, 발사 원점 이전 후퇴 및 벽 통과를 막는다. 박히거나 튕긴 칼은 서버 위치를 유지한다.
- 회수 응답을 기다리는 동안 칼 표시를 고정한다. 프리뷰에서 네트워크 투사체로 바뀔 때도 고정을 유지하며, 거절·반사·수명 만료 시 해제 또는 제거한다.
- 새 회수 입력을 위해 Protocol을 13으로 변경했다. 양쪽 PC에 같은 버전이 필요하다.

## 검증

- JumpChecks.cs: 118개. 양방향 45도, 일방통행 발판, 이동 중 점프, 대시, 천장, 코요테 타임, 입력 재실행.
- Placement.cs: 45개. 실제 Player 충돌체 크기, 바닥·벽·천장·경사, 좁은 틈, 축소 상태, 겹침 복구 중 점프.
- Terrain.cs: 1,152개. 맵 지형과 이동 충돌 회귀 검사.
- MotionChecks.cs: 9개. 바닥·벽·일방통행 발판·아래 점프·점프대·바람·입력 차단.
- Water.cs: 14개 이동 경로.
- Recall.cs: 26개. 양방향 보정 제한, NaN·Infinity, 최대 지연 범위, 발사 원점, 직선 투영, 박힌 칼·튕긴 칼, 얇은 벽·45도 표면, spawn 전 고정 및 전환·거절·수명 만료, 6종 CastInput 직렬화 왕복.
- 개발 빌드 build_415a60aa834c: 성공, 오류 0, 경고 13. 완성된 DLL에서 Protocol 13, 반사 시 고정 해제, 소유권 검사를 직접 확인했다.
- 같은 PC의 에디터 호스트와 개발 빌드를 비공개 UGS Relay 방으로 연결했다. 추가 전송 지연 80ms, 지터 20ms, 손실 2% 조건을 양쪽에 적용했다.
- Relay7: 양쪽의 ±45도 일반·일방통행 발판 정지/점프, 지연 조건 점프, 바닥·경사·세로 벽의 칼 순간이동 좌표와 첫 프레임을 통과했다.
- Relay8: 공중 회수와 반사 시 고정 해제까지 8개 통과. 접속자 칼의 회수 대기 중 이동량은 0이었다. 서버 종료점과 접속자 첫 이동 프레임의 차이는 0.3872로, 기존 전방 추진이 적용된 두 물리 스텝 범위였다. 호스트는 마지막 칼 표시 프레임과 첫 이동 프레임 차이 0.5540을 확인했다.

## 검사 보완과 범위

- 수정 전 45도 정지 상태에서 약 1.47만큼 미끄러짐, 겹침 0.02 상태의 경사 점프가 상승 속도 2.91로 끝남, 중간 벽 때문에 칼 목적지에서 2 이상 전에 멈춤을 재현했다.
- 테스트 발판을 세로로 돌릴 때 다른 플레이어의 낙사가 개입하므로 테스트 인스턴스에만 낙사 기준을 내렸다. 실제 맵 에셋 변경은 없다. 파일 명령 전달의 Windows 읽기/쓰기 경합도 임시 파일 교체로 보완했다.
- 공중 회수 검사에서 사라지는 잔상 좌표를 서버 종료점으로 오인한 것을 수정했다. NetTrace.end는 실제 종료점이다. 종료 잔상과 순간이동 스냅샷은 다른 프레임에 도착할 수 있으므로 각각 비교한다. Relay7에서 저장된 종료점은 (1005.0004, 0.90475), 첫 이동 프레임은 (1005.1956, 0.89298)였다. 보완한 하네스는 Relay8에서 통과했다.
- 에디터가 빌드 전의 스크립트 캐시를 사용한 경우를 발견했다. CLI 강제 import와 CleanBuildCache 컴파일 후 실제 메서드가 갱신된 것을 확인하고 Relay7·Relay8을 실행했다. 에디터 재시작이나 컴퓨터 유즈는 사용하지 않았다.
- 별도 물리 PC 두 대에서의 검사는 이번에 수행하지 않았다. 발사 원점의 예측 오차나 350ms 범위를 넘는 지연에서 모든 시각 차이가 사라진다고 보장하지 않는다.

## 재실행

연결된 에디터에서 JumpChecks.cs·Placement.cs·Recall.cs는 eval_file, MotionChecks.cs는 run_script의 MotionChecks.Main으로 실행한다. 프로젝트 루트에서 Move~/Blade.ps1에 새 Run 이름을 지정하면 비공개 Relay 검사와 종료 정리를 실행한다. 공중 회수만 확인할 때는 -SkipSlopes -Angles @()를 사용한다.
