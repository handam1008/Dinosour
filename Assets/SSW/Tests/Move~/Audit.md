2026-09-17 투사체·이동 네트워크 재검증

Base `42daf9b`를 반영한 상태에서 기존 구현을 점검하고 수정했다. 개발 빌드 `894c089ff08e43c3a166aeca759690ef`로 아래 실제 동작 검사를 수행했다. 일반 실행 빌드 `ed35822e0a3c4bd3961bc136520996f0`도 별도로 생성했다. 두 빌드 모두 오류 0개, 기존 서비스 설정·다른 팀원 소스 관련 경고 10개다. 일반 빌드 경로는 `Builds/Play/Game.exe`, 계측 빌드는 `Builds/Local/Game.exe`다.

확인한 원인과 수정

- 기존 투사체는 로컬 선행 표시를 과거 서버 위치로 0.12초간 끌어당겼다. 프리팹의 NetworkTransform/NetworkRigidbody2D 중복 표시 제어를 제거하고 ShotSync가 실제 표시 위치를 이어받도록 바꿨다. 피해·충돌·생성·제거의 판정은 서버에 남겼다.
- 네트워크 시계 보정이 표시 시간을 뒤로 돌리는 경우를 재현했다. 이동과 투사체의 표시 시간은 앞 방향으로만 진행하며 원격 시간 차이를 완만하게 따라간다.
- 서버가 유실 입력을 대신 적용하고도 처리 번호를 진행하지 않아 같은 시간을 다시 예측하던 경로를 수정했다. 정상 입력, 손실, 장시간 단절 뒤 재동기화를 검증했다.
- 카드 선행 표시에도 실제 프리팹의 중력을 적용했다. 네트워크 자세는 비신뢰 메시지로 최신 값만 소비하고, 늦게 도착한 이미 제거된 투사체 메시지는 즉시 버린다. 대기 자세는 최대 32개, 전송은 물리 진행 기준 최대 약 50회/초, 무수신 외삽은 1초로 제한한다.
- 지형에서 멈춘 표시의 법선이 사라지는 문제와, 반사·회수 전환 후 지형에 붙거나 시전자를 지나치는 문제를 추가 궤적 검사로 찾아 수정했다. 물약 충돌 효과에는 실제 서버 충돌점을 전달한다.
- 클릭 순간 표시 캐릭터 위치로 조준을 갱신한다. 재스폰·선택 단계에서 입력과 이전 예측을 초기화하는 동작은 유지했다.

Audit06/07의 접속자 이동 반응은 약 33ms, 점프는 17/33ms였다. 공격 선행 효과는 검사 명령과 같은 프레임에서 시작했다. 이는 게임 입력 함수 호출부터 표시/본체 변화까지의 측정이며 실제 마우스 장치부터 화면 출력까지의 측정은 아니다. 손실 100%를 3.4초 적용한 뒤 정지·복귀·입력 대기열 복구도 검사했다.

검사 도구 자체에서 발생한 파일 공유 오류와 작성 중인 빈 JSON 읽기를 고쳤다. 관전 중 이동 실패로 보였던 경우도 이 읽기 문제였으며, 보완된 검사에서 양쪽 모두 10회 표본의 최대 위치 변화가 0이었다. 게임 코드를 검사에 맞춰 느슨하게 바꾸지 않았다.

실제 Unity Services / Relay

별도 인증 프로필 두 개로 비공개 방 생성, 참가, 실제 경기 진입, 이동 반응을 확인했다. Audit02에서는 RTT 380ms에서 약 15ms 이동 반응을 기록했다. Audit03의 실제 공격은 호스트 궤적과 접속자 `confirmed=2`, `rejected=0`으로 승인까지 확인했다.

다만 Relay 전체 검사는 완료하지 못했다. RTT가 약 371ms에서 1890ms까지 변했다. 원래 스폰에서 위로 쏜 카드는 약 65ms 뒤 바로 위 발판에 맞았고, 늦은 서버 생성 전에 0.8초 선행 표시가 끝나 해당 발사의 연결 검사는 통과하지 못했다. 다른 실행에서는 Relay HTTP 참가 요청 시간 초과(Curl 28), 연결 대기 실패(`Failed to connect to server.`)가 발생했다. 따라서 실제 Relay의 긴 비행·표시 연결·상대 퇴장까지 모두 통과했다고 주장하지 않는다. 마지막 실행의 양쪽 방 상태는 `joined=false`, `busy=false`이며 검증 프로세스는 종료했다.

범위와 사용 조건

- 현재 온라인 경기 맵인 SuperUltraLegendScene와 마녀·마술사를 대상으로 검증했다. 별도 오프라인 Map_Basic/JumpPad/Teleport/Vanish 씬 전체가 온라인 동기화됐다는 의미는 아니다.
- 지연·손실 시험은 같은 Windows PC의 두 실행 프로세스다. 실제 다른 PC 사이의 통신과 장시간 인터넷 플레이는 미검증이다. 숨긴 실행 창의 스크린샷이 검게 나와 시각 QA 증거로 사용하지 않았다. 렌더러에 연결된 Transform과 실제 UI 이벤트를 검사했다.
- 로컬 반응을 앞당겨도 피해 승인·상대 상태 전달에는 통신 시간이 남는다. 모든 환경에서 무지연·무백섭을 보장하지 않는다.
- 프로토콜과 방 검색 버전이 2로 바뀌었다. 양쪽 모두 새 빌드를 사용해야 한다. 이전 빌드는 같은 방에 섞지 않는다.
- 새 소스·프리팹·테스트 수정은 Assets/SSW 안에만 있다. 팀원 폴더는 직접 수정하지 않았다. 프리팹은 Unity CLI 연결 에디터로 편집했고 네트워크 식별 해시를 유지했다. 씬·발판·배경은 수정하지 않았으며 에디터를 MainMenu 편집 모드로 복귀했다.

재현과 근거

`Audit.json`에 빌드/어셈블리 해시, 조건, 검사 목록, 원본 기록 SHA256을 저장했다. 상세 궤적과 로그는 위 표의 `Logs/` 경로에 있다. 이전 `Results.md`/`Results.json`은 이전 수정의 역사 기록이다.

새 Run 이름으로 `Flight.ps1` 실행 뒤 `Trajectory.py Logs/Move/<Run>`을 실행한다. 특수 투사체는 `Special.ps1`와 `Specials.py`를 사용한다. 일반 동작은 `Verify.ps1`, 실제 방은 `Relay.ps1`이다. 스폰 검사는 Unity CLI로 에디터 Play를 켠 뒤 `Spawn~/Verify.ps1 -Build Builds/Local/Game.exe`를 실행한다. 테스트 출력에 개발용 계측이 필요하므로 Development 빌드를 사용한다.
