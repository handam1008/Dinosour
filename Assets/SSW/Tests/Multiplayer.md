# 대전 테스트

소스와 네트워크 프리팹은 Assets/SSW에 있다. 다른 팀원 폴더는 수정하지 않는다. 실행 파일은 Builds/Local/Game.exe에 생성한다.

## 두 창 실행

1. MainMenu 씬에서 Tools → 대전 테스트를 연다.
2. 코드나 프리팹을 수정했다면 테스트 빌드를 누른다.
3. 클라이언트 열기를 누른다. Unity가 Play에 들어가고 별도 게임 창을 연다. 두 창 모두 원래 메인 메뉴에서 시작한다.
4. 각 창의 직업 설정에서 마녀 또는 마술사를 선택한다.
5. 각 창에서 Play → 매치메이킹을 누른다. 두 사람이 연결되고 맵과 플레이어가 준비되면 VS 연출이 나온 뒤 증강 선택 화면에 들어간다.
6. 양쪽에서 증강을 하나씩 선택하면 전투가 시작된다.

호스트 시작 버튼은 필요 없다. 클라이언트 열기는 게임 메뉴를 건너뛰지 않는다. 별도 창은 test-client 인증 프로필을 써서 같은 PC에서도 서로 다른 계정으로 접속한다. 각 테스트 프로필은 직업 선택도 따로 저장한다. 이미 해당 창이 열려 있으면 중복 실행하지 않는다.

매치메이킹은 실제 Unity Multiplayer Services의 세션 검색과 Relay 연결을 사용한다. 상대가 없으면 대기하고 취소로 돌아갈 수 있다. 동시에 두 대기 방이 생긴 경우에도 한 방으로 합류한다. 이 경로는 인터넷 연결이 필요하다.

## VS 연출

맵과 두 플레이어가 생성되면 Intro 상태에서 각자 자기 프로필을 왼쪽에 표시한다. 직업에 맞는 공룡과 모자를 사용한다. 프로필의 초록 상태 점은 표시하지 않는다. 왼쪽 대사는 “좆밥새키야 ㅋ”, 오른쪽 대사는 “개벌레 새키가 ㅋ”다.

배경은 실제 경기 카메라를 계속 렌더링해 흐리게 보여준다. 검은 띠와 양쪽 정보가 들어온 뒤 VS가 찍히고, 약 1.4초 뒤 양쪽 연출 완료를 확인해 증강을 나눠준다. 퇴장은 0.4초다. 상대 로딩이 늦으면 완성된 VS 화면에서 기다린다. 연출이 끝나기 전에는 증강 선택과 전투를 시작할 수 없다. ESC 메뉴는 VS 위에 열린다.

UI/Vs.prefab의 Hold로 정지 시간을, Left와 Right의 VsCard → Line으로 대사를, Blur의 Radius로 흐림 정도를 조절한다. 화면 구성은 편집 가능한 uGUI 오브젝트이며 다른 팀원 프리팹을 수정하지 않는다. Tools → VS 미리보기는 현재 씬의 카메라 위에 연출만 재생한다. 실제 매칭과 증강 연결은 두 창 실행 절차로 확인한다.

닉네임이 있다면 연결 전에 NetGame.SetProfile(Fighter.Create(name))을 호출한다. 서비스에서 인증된 PlayerName이 있으면 기본값으로 사용하고, 이름이 없으면 플레이어 1·2를 표시한다. 개발 실행 인자 --net-name으로도 이름을 지정할 수 있다.

## 방 만들기와 참가

- 방장: Play → 방 만들기 → 이름과 선택 사항인 비밀번호·숨김 설정 → 방 만들기.
- 참가자: Play → 방 들어가기 → 방 목록에서 참가, 또는 참가 코드와 비밀번호 입력 → 코드로 참가.
- 비밀번호는 8~64자다. 숨긴 방은 목록에 표시하지 않고 코드로 참가한다. 코드의 영문 대소문자는 구분하지 않는다.
- 두 사람의 네트워크 연결과 직업 정보가 준비되면 방장의 게임 시작 버튼이 활성화된다.
- 방 나가기나 매칭 취소는 해당 세션을 정리하고 Play 메뉴로 돌아간다.

방 화면은 기존 Play 버튼을 사라지게 한 뒤 같은 배경 안에서 전환한다. 별도 팝업 테두리를 사용하지 않는다.

## 전투 조작과 시점

각 화면에서 자기 캐릭터가 왼쪽, 상대가 오른쪽에서 시작한다. 오른쪽 스폰을 배정받은 화면은 카메라와 좌우 입력을 함께 반전한다. 마우스 조준, 체력바, 카드 숫자는 자신의 화면을 기준으로 동작한다. 캐릭터가 교차해도 경기 중 시점은 바뀌지 않는다. 서버의 실제 위치와 물리 판정은 모두 같다.

마술사는 왼쪽 마우스를 누르는 동안 숫자가 바뀌고 놓으면 카드를 던진다. 오른쪽 마우스로 문양을 고른다. 마녀는 자동으로 바뀌는 포션을 왼쪽 마우스로 던진다. 이동과 점프는 기존 입력을 사용한다.

ESC → 계속하기는 조작을 재개한다. 나가기는 연결을 종료하고 메인 메뉴로 돌아간다. 메뉴를 열 때 준비 중이던 카드는 취소한다. 온라인 메뉴를 열어도 상대의 시간은 멈추지 않는다. 한 명이 죽으면 라운드 승패를 판정하고, 4세트를 먼저 이기거나 상대가 연결을 끊으면 최종 결과를 표시한다. 호스트 이전은 하지 않는다.

## 서비스 담당 코드와 연결

MultiplayerSessionManager는 인증·방 검색·생성·참가·취소와 시작을 담당하고 NetGame은 네트워크 전투를 담당한다. 세션의 room 모드는 사용자 방, quick 모드는 자동 매칭 방이다. 서로의 검색 결과에 섞이지 않는다.

별도 연결 코드를 쓴다면 연결 전에 NetGame.GetOrCreate(), SetLocalJob(job), Prepare() 순서로 호출한다. Prepare는 기존 NetworkManager.Singleton을 사용하거나 SSW의 NetManager 프리팹을 만든다. 이후 담당 코드에서 transport를 설정하고 StartHost 또는 StartClient를 실행한다. 연결된 로컬 플레이어의 직업 정보는 자동 전달된다.

서버는 SetJob(clientId, job)으로 직업을 전달할 수 있다. Ready가 true이면 LoadScene("SuperUltraLegendScene")을 호출한다. 맵이 이미 네트워크로 열려 있다면 StartMatch()를 호출한다. 기본 자동 PlayerPrefab 대신 NetGame이 두 플레이어를 한 번씩 생성한다.

Ended 이벤트는 한 번 발생한다. MatchState.Winner는 NGO 클라이언트 ID이고 Reason은 Knockout, Left, Draw 중 하나다. 개인 결과 비교에는 LocalId를 사용한다. 전적 저장과 랭킹은 서비스 담당 코드에서 이 이벤트에 연결한다.

## 구조

- NetPlayer: 입력 검증, 서버 이동, 소유권.
- NetHealth: 서버 체력 복제.
- NetCast, NetCard, NetPotion, NetZone: 서버 추첨·발사·충돌·효과.
- NetDraft, NetDeck, NetBuff: 서버 증강 선택과 적용.
- NetArena, NetMatch, MatchUI: 스폰 위치, 경기 상태, 결과와 종료 메뉴.
- Fighter, Vs, VsCard, Blur: 프로필 동기화, VS 연출, 직업 초상, 경기 배경 흐림.

온라인 공통 증강은 거인·흡혈·광전사·자신감·유리 대포·쿨타임 감소 여섯 종류다. 직업 증강은 기존 마녀·마술사 풀을 사용한다. 포션은 RYU의 기존 데이터를 참조하며 그 폴더의 코드는 수정하지 않는다.

## 검증

VsChecks.txt와 VsState.json은 실제 매칭의 Intro → Draft → Playing, 증강 카드 레이캐스트, 마술사 발사, 재매칭과 연출 중 ESC 종료 검증이다. Vs.png는 실제 경기 카메라를 배경으로 한 연출 캡처다. Run~/VsFilm에는 진입·정지·퇴장·증강 진입을 연속 캡처한 원본과 시간이 있다.

MenuChecks.txt와 MenuState.json에 실제 메뉴를 통한 온라인 생성·참가·매칭·전투 검증을 기록한다. NetChecks.txt는 기존 전투 검사, ViewChecks.txt는 각자 왼쪽 시점 검사 기록이다. ViewChecks의 이전 로컬 자동 실행 설명은 현재 메뉴 실행 방식으로 대체됐다.

같은 PC의 서로 다른 인증 프로필 두 개로 실제 Unity 서비스와 Relay를 사용해 확인했다. 물리적으로 다른 두 PC와 전적 저장·랭킹은 이번 검사 범위에 포함하지 않는다.

NetProbe와 MenuProbe는 Editor 또는 Development Build에서만 포함된다. MenuProbe의 버튼 검사는 실제 EventSystem 레이캐스트를 통과한 버튼만 클릭한다. 발사 검사는 InputSystem의 마우스 눌림·놓음 이벤트로 수행한다. Run~ 폴더는 검사 중의 로그·명령·스크린샷을 담으며 Unity 에셋 가져오기에서 제외한다.

서비스 없이 직접 접속하는 개발용 경로도 유지한다.

```text
Game.exe --net-mode host --net-job Magician --net-port 7777
Game.exe --net-mode client --net-job Witch --net-address 127.0.0.1 --net-port 7777
```
## 세트와 라운드

최대 7세트 중 4세트 선승이며, 각 세트는 최대 3라운드 중 2라운드 선승이다. 상단 숫자는 세트 점수이고 숫자 아래 세 원은 각 라운드의 승리 위치를 표시한다. 세트가 바뀌면 원만 초기화한다. 동시 사망은 점수 없이 같은 라운드를 재개한다.

시작 시 양쪽 모두 공용 증강 3개 중 하나를 고른다. 세트가 끝나면 패자만 추가 선택한다. 개인 누적 1·3번째 패배에는 공용과 직업 증강을 각각 3개 중 하나씩 고르고, 2번째 패배에는 공용만 고른다. 최종 패배 후에는 선택하지 않는다. 기존 증강은 유지하고 매 라운드 체력·위치·공격·임시 효과를 초기화한다.

RoundChecks.txt는 두 실행 파일의 7세트 4:3 종료까지 98개 검사와 에디터의 동시 사망·카드 클릭·연결 종료 4개 검증 결과다. RoundState.json은 최종 호스트 상태, RoundPreview.png는 테두리와 발광을 다듬은 실제 게임 화면이다. Rounds~/Rules.cs는 Unity CLI eval_file로 실행하는 순수 규칙 검사다.

## 라운드 전환과 선택 제한 시간

세트 안의 라운드 사이에는 카드를 다시 고르지 않는다. 사망 시 왼쪽에서 검은 띠가 들어와 승자 이름을 표시하고 오른쪽으로 빠져나간다. 경기장 전체를 가리지 않으며, 재스폰 후 다음 라운드를 시작한다. 무승부는 별도 승자 없이 같은 라운드를 재개한다.

공용과 직업 선택에는 각각 서버 기준 10초가 주어진다. 선택 화면에 종류와 남은 초를 표시하며, 먼저 고른 플레이어와 세트 승자에게는 상대가 증강을 고르는 중이라는 안내와 상대의 남은 시간이 보인다. 시간 초과 시 제시된 카드 중 하나를 자동 선택한다. 마감 전에 클릭한 카드는 선택 애니메이션이 남아 있어도 유지한다.

FlowChecks.txt에는 두 클라이언트의 7세트 검사 145개와 에디터의 실제 클릭·마감 직전 선택·전환 검사 11개를 기록했다. DraftTimer.png와 JobTimer.png는 공용·직업 선택, DraftWait.png는 상대 대기, RoundWipe.png는 승리 띠 화면이다. Flow~/Verify.ps1은 프로젝트 루트에서 실행하며 -Build로 최신 개발 빌드 경로를 지정한다. 검증 실행마다 -Run에 새 이름을 사용한다.


## 증강 선택과 관전

자신이 고를 때는 직업에 맞는 큰 공룡을 왼쪽에 연하게 표시한다. 첫 공용 선택은 상대에게 공개하지 않는다. 이후 세트 패자에게 주어지는 선택은 승자가 관전하며, 같은 카드와 선택자의 공룡을 오른쪽에 보여준다.

호버한 카드는 확대하고 금빛으로 강조한다. 선택자의 커서 위치와 선택한 카드도 동기화하며, 커서 이동 자취는 작은 금빛 입자로 흩어져 사라진다. 커서가 화면 밖으로 나가면 잔광도 사라진다. 관전자는 카드를 선택하거나 캐릭터를 움직일 수 없다. 공용 다음 직업을 고르는 순서와 각각 10초 제한은 그대로다.

Resources/UI/Draft.prefab에서 공룡·카드·커서 구성을 편집한다. DraftScreen은 선택 화면, DraftPortrait는 공룡, DraftTrail은 커서 잔광, DraftWatch는 서버 검증과 관전 상태 동기화를 담당한다.

WatchChecks.txt는 두 개발 실행 파일에서 양쪽 역할을 바꾼 관전 검사 32개다. 초기 선택 비공개, 카드·호버·커서 동기화, 관전자 클릭·이동 차단, 공용 다음 직업, 잔광 소멸, 마감 직전 선택을 확인했다. WatchState.json과 DraftPortrait.png·DraftWatch.png·DraftWatchJob.png는 에디터와 실행 파일을 연결한 실제 선택·관전 화면이다. Watch~/Verify.ps1은 프로젝트 루트에서 -Run에 새 실행 이름, -Build에 최신 개발 빌드를 지정한다. 이 검사는 localhost 직접 접속이며 인터넷 서비스 검증과 구분한다.

같은 관전 빌드에서 기존 7세트 흐름 145개도 재검사하여 총 177개를 통과했다. 결과는 WatchChecks.txt에 함께 기록했다.
