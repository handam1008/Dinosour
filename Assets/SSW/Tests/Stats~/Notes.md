최신 CLI 실행에서 808개 검사와 172바이트 패킷 직렬화를 통과했다. 결과는 `Logs/Stats/BakeLatest.json`과 `Logs/Stats/BakeResult.json`에 남아 있다. NGO 임시 등록 정리와 기존 항목·값·순서 보존 검사도 포함한다. 실제 멀티 플레이 결과는 별도다.

실행 전에 Play와 빌드를 멈추고 `Setup.cs`로 운영 책자와 원본 설정을 생성·베이크한다. 원본으로 설정한 씬에 저장하지 않은 변경이 있으면 이 검사는 저장하거나 덮어쓰지 않고 실패한다. `Assets/SSW/Tests/StatBakeCheck`가 이미 존재해도 실패하며 기존 폴더를 지우지 않는다.

검사 범위:

- 여섯 직업의 저장된 책자와 현재 원본 추출 결과를 비교하고, 체력·이동·공격·투사체·재사용 시간 등을 원본 `SerializedObject` 값과 별도로 비교한다.
- 실제 프리팹 복사와 variant를 임시 SSW 경로에 만들어 자식 override 우선, 상속된 부모 변경, 연결된 스킬 SO·투사체 크기 변경을 검사한다. 비균일 크기는 Scale과 Aspect로 보존한다.
- 임시 책자·포션 목록·메모리상의 StatSources를 명시 참조로 구성해 전체 베이크와 동일 입력 재베이크를 검사한다. 운영 책자와 설정을 베이크 대상으로 넘기지 않는다.
- 실제 NGO FastBufferWriter/FastBufferReader로 여섯 직업과 모든 필드가 서로 다른 패킷을 왕복한다. typed Equals 외에도 각 필드를 별도로 비교해 직렬화와 Equals에서 같은 필드가 함께 빠지는 경우도 검출한다.
- NaN, 무한 좌표, 탄창 범위, 0 체력·Aspect·원본 투사체 크기, 중복·누락 직업, 필수 에셋 참조와 씬 루트 누락을 검사한다.
- 포션 ID와 원본 SO 참조를 보존하는지, 새 참조가 뒤에 추가되는지, 복사한 테스트 SO의 weight 변경이 재베이크 없이 추첨에 반영되는지 검사한다. 팀원 원본 weight는 바꾸지 않는다.
- Play·빌드·import 연결은 등록 속성·인터페이스 및 컴파일된 IL의 메서드 참조로 확인한다. 실제 Play 전환·빌드를 시작하거나 운영 전체 베이크를 호출하지 않는다. 따라서 실제 Play와 빌드 수명주기의 검증은 부모 작업에서 별도로 수행해야 한다.
- preview 씬과 임시 복사 씬으로 성공·실패 경로를 검사하고, 기존 씬의 활성·로드·dirty 상태를 비교한다. 원본 자산 파일 해시와 운영 객체의 값·dirty 상태도 종료 시 비교한다.
- NGO 기본 등록 목록은 실행 전 항목을 기록하고, 정리 직전 목록에서 이번 실행이 생성한 프리팹 경로의 자동 등록만 제거한다. 나머지 항목의 값과 순서, 실행 전 기존 항목의 보존을 비교하고, 임시 자산 삭제 후에도 같은 목록인지 확인한다. 기존 목록 전체를 덮어쓰거나 이번 실행과 무관한 missing 참조를 제거하지 않는다.

임시 에셋은 생성 전에 정확한 경로의 충돌을 검사한다. finally에서 테스트 프리팹만 `Assets/DefaultNetworkPrefabs.asset`의 등록 목록에서 먼저 제거·저장한 뒤, 이 실행이 생성 대상으로 기록한 정확한 경로만 AssetDatabase.DeleteAsset으로 정리한다. 등록 정리에 실패하면 프리팹 삭제를 멈추고 오류를 보고한다. 폴더 안에 예상하지 않은 파일이 남으면 폴더를 삭제하지 않는다.

출력은 통과 검사 수, 직업별 핵심 추출값, 패킷 바이트 수다. 실패하면 해당 검사 이름의 예외를 반환한다. 스크립트가 통과해도 서버·클라이언트의 실제 플레이 결과나 애니메이션 스윕까지 검증했다는 뜻은 아니다. 칼잡이 HitSize/HitOffset은 정지 자세 AABB이고, 원본 애니메이션에 따라 회전하는 OBB와 같지 않다. 코드에만 존재하는 유지 상수, 패링 박스·잭팟·직업 증강별 추가 효과 등 데이터 모델 밖의 항목은 운영 추출 보고서의 제약을 따른다.
