# 공용 증강·총잡이 연동

RealCommonAugmentPool의 공용 30개를 Network/Deck에 등록했다. 공용 후보는 직업과 관계없이 이 풀의 항목만 사용한다. 서버가 선택·피해·회복·방어·설치물·상태 효과를 결정하고, 각 클라이언트는 동기화된 상태와 이펙트를 표시한다. 우클릭은 모든 직업의 일반 방어이며 검사의 E 패링은 유지한다.

BuffHealth, BuffGuard, BuffSkill은 체력·방어·능력을 나눈 멀티 구현이다. BuffArea는 설치물과 회복 장판의 판정, BuffFx는 시각 표현을 맡는다. 원본 AJH 컨트롤러와 KDH 스크립트는 수정하지 않았다. 죽음의 무도는 실제 방어와 구분해 명중 효과를 유지하며, 지연 피해의 회복량은 실제 감소한 체력을 따른다.

총잡이는 원본 FirePos, Tanchang의 9개 Ammo, 개별 3초 충전 표시와 EffectPool을 연결했다. 총알과 적중 판정은 서버에서만 실행하며 예측 탄환과 원격 탄환의 시각 이펙트는 각자의 풀에서 재사용한다. 강화탄 피해 30, 탄속 30, 중력 2, 강화탄 2회 적중 후 진화, 축소 재사용 5초를 원본에서 읽었다. 독 재적중은 다음 피해 시점을 밀지 않고 남은 횟수를 갱신한다.

새 공용 카드가 기존 CommonAugmentType에 해당하면 CommonAugment 에셋을 만들고 RealCommonAugmentPool과 Network/Deck 양쪽에 등록한다. 새로운 효과 유형은 서버 처리와 시각 이벤트 연결이 추가로 필요하다. 이펙트 프리팹 생성만으로 서버 동작이 자동 연결되지는 않는다. 배포 시 양쪽 클라이언트에 동일한 프로토콜 14 빌드를 사용한다.

에디터 검사:

- Health.cs: 체력 조합·권한·지연 피해 34개.
- Motion.cs: 공중 점프·동결·이동·크기·조준 직렬화 50개.
- Guard.cs: 방어 설정·설치물 충돌 29개.
- GunChecks.cs: 탄창·충전·원본 수치·총구·독·시각 에셋·풀 정리·진화 복구·낙하 회전·축소 잔상 93개.
- Assets.cs: 공용 풀·직렬화 참조·시각 에셋 77개.
- Move~/JumpChecks.cs: 경사·점프 회귀 118개.

Verify.ps1은 개발 빌드와 에디터를 실제 UGS Relay 비공개 방으로 연결한다. 공용 증강, 80ms 지연·20ms 지터·2% 손실, 라운드 초기화와 Gun.ps1의 총잡이 검사를 수행한다. 테스트는 현재 StartMenu의 미저장 상태를 보존하고 자신이 만든 접속자 프로세스만 종료한다.

최신 Base 병합으로 원본 식별자가 바뀐 Map13과 Map16은 멀티 프리팹의 원본·스폰·기믹 참조를 다시 연결했다. 사쿠라 맵은 기존처럼 KDH의 실제 편집 프리팹과 SakuraField를 사용한다. 맵 14개 518항목과 기존 맵 연출 480항목 검사에 통과했다.

실제 Relay 검사 61개를 통과했다. 검증용 에디터 호스트와 별도 개발 빌드 접속자에서 공용 30개 복구·공격·방어·회복·설치물·공중 점프·동결·라운드 초기화, 양쪽 총잡이 일반탄 15/강화탄 30·탄약 9개·조준·10종 증강·진화·지속 피해·풀 반환을 확인했다. 지연 80ms, 지터 20ms, 손실 2% 조건에서도 예측 탄환 연결과 종료가 정상이며 발사 거절은 없었다. 개별 효과 비교용 시나리오는 서버 기본 체력을 100으로 맞추며 실제 에셋의 체력 80은 변경하지 않는다. 원격 상태는 전송 지연을 고려해 최종 일치 여부를 검증한다.

실행 근거는 Logs/Common/Results.json, Relay26C·Relay26E·Relay26F, 최종 총잡이 완료 결과는 Relay26F/Result.json에 있다. 로그의 주기적 상태 비교는 실제 인터넷 두 PC의 최대 핑이나 끊김 부재를 보장하지 않는다. 에디터 StartMenu의 미저장 상태가 테스트 전후 동일함도 확인했다.
