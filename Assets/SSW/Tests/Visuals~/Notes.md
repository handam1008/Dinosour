# 플레이어 스킨과 잔상 연결

팀원 커스터마이징 구현은 `dc8d3394343ca7c7f0f47fc580105da8ff4c09e6`에서 받았고, 최종 통합에는 메뉴·방 수정 `1f38f067ff93ad50834b211d8447a7442b24d8f3`까지 포함했다. 팀원 원본 파일과 저장 정책은 수정하지 않았다.

- 기존 `DinoSkinStorage.LoadId()`의 선택을 `Fighter.Skin`에 담아 전달한다. 실제 네트워크 플레이어의 원본 `DinoSkinApplier`가 이를 적용하며, 상대 선택을 로컬 저장값으로 덮어쓰지 않도록 `applyOnStart`는 껐다.
- 원본 `SpeedAfterimage`를 실제 플레이어에 연결했다. 생성 간격 0.08초, 소멸 0.3초, 색상과 정렬 오프셋은 원본 Witch 프리팹에서 복사했다. 속도 포션의 실제 남은 시간을 서버에서 받아 상대 화면에도 재생한다. 피해·강화 효과를 클라이언트에서 다시 실행하지 않는다.
- `SpeedTrail`은 명시적으로 연결한 30개 렌더러 중 현재 보이는 것만 원본 효과에 전달한다. 원본에 공개 연결·남은 시간 API가 없어 내부 필드 두 곳을 제한적으로 연결하며, 매 프레임 배열을 만들지 않는다. 플레이어가 제거돼도 기존 잔상은 소멸을 마친 뒤 정리한다.
- 패킷 변경으로 프로토콜은 **22**다. 양쪽 PC를 같은 버전으로 실행해야 한다.

## 프리팹 보존

`Setup.cs`를 Unity CLI로 실행했다. 저장 전 프리팹 백업과 해시, 열려 있는 프리팹의 미저장 상태, 저장 직전 동시 변경을 확인했고 기존 155개 컴포넌트 직렬화 값이 보존됐다. 기존 물리 머티리얼 설정도 유지된다. 근거는 `Logs/Visuals/Setup.json`과 `Logs/Visuals/BeforeSetup/Player.prefab`이다. 이미 수정한 프리팹에 예전 백업으로 Setup을 재실행하면 중단하도록 되어 있다.

멀티 검증은 한 PC의 에디터 호스트와 개발 빌드 접속자로 진행했고 지연 60ms·편차 10ms를 주었다. 두 PC Relay 실전 검증은 아니다. 접속자 스킨은 실제 연결된 SpriteLibrary까지 확인했으며 화면 픽셀이나 접속자 렌더러 스프라이트까지 확인한 것으로 보지 않는다. 포션 확인은 서버의 실제 적용 경로를 호출했으며 투척 입력·비행 검사는 포함하지 않는다.

첫 Menu01·Menu02 시도는 재생 전환 연결 재설정과 테스트의 버튼 위치 가정 때문에 중단됐다. Afterimages01은 준비 단계에서 라운드가 끝나 실제 효과 확인 전에 중단됐다. 기존 플레이어의 낙하와 배우 교체 사이 빈 프레임을 막도록 안전 위치로 이동하고 교체를 같은 프레임에 처리한 뒤 빠른 확인을 통과했다. 실패한 시도는 제품 기능 통과 근거로 사용하지 않았다.

각 실행은 생성한 접속자를 종료하고 원래 Crate 씬을 미저장 변경 없이 복원했다. 사용자 보관 파일 5개의 해시도 유지됐다. 전체 직업·사망·라운드 회귀 검사는 이번 범위에서 실행하지 않았다.

## 재실행

`Hazards.ps1 -Run <새 기록 폴더 이름> -VisualFile Skins -Build <개발 빌드 경로>` 또는 `-VisualFile Afterimages`를 사용한다. 기본값은 제한된 빠른 확인이다. 빌드에는 현재 프로토콜과 개발용 NetProbe가 포함돼 있어야 한다. `Menu.ps1`은 원래 PlayerPrefs와 씬을 복원한다.
