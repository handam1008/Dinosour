# 2026-09-27 전투·메뉴 수정

Unity 6000.5.2f1, 프로토콜 23. 효과 검증 기준은 Base `3e5d1da`이며, 이후 Base `992a0f7`의 팀원 룰렛·맵 경계 변경을 `28aaaba`에 충돌 없이 통합했다.

## 변경

- 물 배경 전체를 합치던 맵 프레임 계산을 네 방향 플레이 경계 기준으로 변경했다. Map08·Map12의 카메라 중심 Y는 -1.5다. 원본 갱신 시에도 같은 계산을 사용한다.
- 피해 숫자는 캐릭터 몸체 SpriteRenderer에 고정한 참조로 위치를 구한다. 멀리 이동한 무기·잔상·효과 렌더러를 포함하지 않는다.
- 총잡이의 장전과 탄 충전 경과 시간을 증강 선택 중 정지하고 전투 재개 시 남은 시간부터 이어간다.
- 경기 메뉴의 나가기를 항복으로 바꿨다. 서버가 요청자의 참가 여부를 확인한 뒤 상대 승리 결과를 전파하고 결과 화면 연결을 유지한다.
- 원본 마녀 프리팹에 저장된 음수 spreadAngle은 기본 24도로 베이크한다. 호스트 발사와 접속자 예측이 같은 수치를 사용한다.
- 점수 보고는 서로 다른 참가자 둘이 실제 전투를 진행한 정상 4세트 승리 결과에 한정한다. 방 대기·연습·미완료 결과는 보고하지 않는다. 기존 항복·접속 종료의 점수 미보고 정책은 유지한다.
- MainMenu의 ProfileInfo가 결과 보고 이벤트와 메뉴 재진입 조회를 반영한다. 뒤늦은 과거 조회 응답이 최신 결과를 덮지 않도록 요청 순서를 검사한다.
- Player 프리팹의 저장된 네트워크 ID 3316593943이 Netcode가 계산한 2334970032와 달랐다. 에디터 로드 상태에 따라 빌드와 접속 구성이 달라지는 원인을 확인하고 Netcode OnValidate로 생성한 값을 프리팹에 저장했다. 프로토콜 비교와 프리팹 동일성 검사는 유지한다.

## 추가한 검사 증강

기존 KHG 프로토타입 효과 6종을 서버에 연결했다. 작업 중 Base `3e5d1da`에 팀원이 올린 SO 여섯 개를 가져와 임시 SO 대신 연결했다. 이름·GUID·설명은 팀원 자산을 유지하고 잘못 지정된 기존 효과 type을 새 타입으로 바꿨다. 기존 ID는 보존하고 85는 빈 예약 슬롯으로 둔다. 새 ID는 86–91이며 직업 후보는 총 60개, 검사는 10개다.

최신 SO 설명을 기준으로 쿨감 2초·속박 0.5초·발도 적중 즉시 회복을 적용했다. 설명에 피해량이 없는 출혈은 기존 총 피해 6을 유지하며 적중 후 1초와 2초에 각각 3을 적용한다. 이전 실행 기록의 3초·1초·다음 평타 회복은 변경 전 증거다.

| ID | 이름 | 효과 |
|---|---|---|
| 86 | 연마 | 패링 성공 시 돌진 잔여 대기시간 2초 감소 |
| 87 | 출혈 | 적중 후 1초와 2초에 각각 3 피해 |
| 88 | 화뢰 | 적중한 상대 0.5초 속박, 재발동 대기 1초 |
| 89 | 생명 탈취 | 발도 실제 피해의 30% 즉시 회복, 돌진 종료 후 4초간 돌진 피해 15% 증가 |
| 90 | 자연의 섭리 | 1초 정지 후 0.5초마다 HP 1 회복 |
| 91 | 성장 | 전투 중 초당 0.1씩 크기·평타 범위 증가, 최대 3배, 라운드 재생성 시 초기화 |

이미 구현된 효과의 카드 추가는 해당 SO 타입·효과 종류를 지정하고 Network/Deck에 등록한다. 새 효과는 서버 수신 코드도 필요하다. 이 여섯 항목은 SwordCast·SwordEffects에 연결되어 있다.

## 실행 증거와 범위

`SwordLinks.cs`는 에디터 호스트와 별도 Windows 접속자 프로세스를 사용하고 양방향 지연 60ms·지터 10ms를 설정한다. 검사 효과는 각 소유자에 대해 서버 JobCast.Apply를 호출한다. 정밀조제는 실제 호스트/접속자 NetCast 입력, 카드 선택은 UI, 항복은 접속자 MatchUI 경로를 사용한다. 이 결과는 실제 두 PC나 외부망 전투 검증이 아니다.

- `Logs/Boundary/SwordLinks23B/SwordLinks.json`: 성공 검사 135개. 여섯 증강 중 정지 회복은 준비 시점 문제로 실패하여 C에서 다시 검사했다. 카드 선택 6종, 피해 숫자, 선택 중 장전 정지, 성장·재생성, 카메라, 항복 전파는 통과했다. 전체 실행을 성공으로 집계하지 않는다.
- `SwordLinks23C`: 정지 회복은 호스트와 접속자 소유 캐릭터 모두 통과했다.
- `SwordLinks23D`: 위치 이동의 새 epoch가 접속자에게 도착한 뒤 실제 입력을 보내도록 준비를 고쳤다. 양쪽 정밀조제에서 3개 투사체의 각도 차이 12도·전체 24도와 접속자 비행 분리를 확인했다.
- C–E의 조합 실패는 돌진 사이에 검사 대상까지 반복 순간이동시켜 입력 시계를 재설정한 준비 문제였다. 마지막 조합 검사는 시전자 위치·시계를 유지하며 실제 패링 후 기본 쿨다운을 기다린다. 대기시간·효과 수치와 프로토콜 검증을 우회하지 않는다.
- `SwordLinks23J`: 검사 조합과 카메라 25개 검사 통과. 실제 패링의 2배 피해와 새 15% 효과가 양쪽 소유자에서 함께 적용됐다. Map08·Map12는 양쪽 카메라 중심 Y=-1.5이며 호스트 화면 PNG로 플레이 구역 표시를 확인했다. 숨긴 Windows 접속자 창의 화면 캡처는 검게 저장되어 시각 검증 자료로 사용하지 않는다. 접속자는 카메라·맵 동기화 값을 확인했다.
- F–I는 위 네트워크 ID 불일치로 시작 전에 중단됐다. 재빌드만으로 저장된 잘못된 ID를 고칠 수 없었으며, `Logs/AugmentLink27/NetworkIds.json`과 시작 시 `*.config.json`으로 생성값과 양쪽 프리팹 목록을 검증한다.
- `SwordLinks23K`: 수정된 프리팹을 다시 로드한 에디터와 별도 플레이어의 구성 해시가 모두 `7118F17A27BD63F8`로 일치했다. 정밀조제 양쪽 입력과 접속자 항복 포함 13개 검사 통과, 양쪽 종료 및 깨끗한 MainMenu 복귀를 확인했다.
- `SwordLinks23L`: 최신 Base SO와 변경된 효과로 100개 검사 통과. 양쪽 소유자에서 2초 쿨감, 1·2초 출혈, 0.5초 속박, 발도 실제 피해의 30% 즉시 회복 및 평타 중복 회복 없음, 4초 증폭 만료, 새 SO 여섯 개 UI 선택을 확인했다. 조합 검사는 첫 실제 평타 패링 뒤 두 번째 투사체 피해를 CombatDamage로 주입해 복수 피격 패링과 증폭의 상호작용을 검사했다. 두 번째 피격은 실제 투사체 입력이 아니다. 이 실행은 `build_1c324478117c`를 사용했다.
- `Logs/AugmentLink27/RoomScore.json`: 별도 UGS 익명 프로필에서 비공개 방 생성·퇴장 2회. 전후 랭킹 등록 없음, Ended/Reported 이벤트 각각 0회, 종료 시 방 없음. 기존 계정의 점수를 쓰지 않았다.
- `Logs/AugmentLink27/ProfileScore.json`: 실제 Reported 이벤트에 검사용 결과를 전달해 연결된 메뉴 텍스트가 `1234점`으로 갱신됨을 확인했다. Cloud Code의 실제 경기 점수 지급 검사는 아니다.
- `Logs/AugmentLink27/FinalBuild.json`: 통합 커밋 `28aaaba`에서 기본 씬 목록으로 Windows 일반 빌드 `build_42d2f8bd300a` 성공. 오류 0개, 기존 팀원 코드·프로젝트 설정 경고 10개. 결과는 `Builds/Final23/Game.exe`다.
- `Logs/AugmentLink27/FinalInspect.json`과 `Protocol.json`: 최종 SO 여섯 개 연결, 검사 후보 10개, 예약 ID 85, 두 맵 프레임, Player 네트워크 ID, 피해 숫자 참조와 최신 검사 수치를 다시 확인했다. 최종 실행 파일과 에디터의 프로토콜은 모두 23이며 배포 파일에는 NetProbe가 없다. 에디터는 수정되지 않은 MainMenu에서 Play를 정지한 상태다.

재현:

