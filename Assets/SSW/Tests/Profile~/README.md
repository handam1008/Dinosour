# 프로필 커스터마이징·점수 갱신

2026-09-27, Unity 6000.5.2f1, Base `432e25f` 기준.

SkinPreview는 MainMenu의 기존 커스터마이징 버튼 24개를 명시적으로 참조한다. 원래 버튼의 저장 동작을 유지하며 선택된 SpriteLibrary의 Idle 프레임을 프로필에 전달한다. 직업 모자·대기 애니메이션·재진입 시 저장된 선택을 유지한다.

ProfileScores는 메뉴 씬 밖에서도 MatchReporter.Reported를 받아 계정별로 결과를 보관한다. ProfileInfo는 로그인 완료·메뉴 활성화·결과 수신·앱 포커스 복귀에 맞춰 표시를 갱신한다. ProfileScore는 결과보다 늦게 끝난 조회와 순서가 뒤바뀐 조회를 거부한다. 경기 결과 직후의 오래된 리더보드 값도 결과를 덮지 않으며 같은 점수가 조회되면 확인된 값으로 전환한다. 조회 실패 시 마지막으로 확인한 점수를 유지한다.

- `Scores.cs`: 점수 0, 승리·패배, 조회 순서 역전, 결과 전후 조회, 계정별 상태 분리 등 10개 검사 통과. 증거는 `Logs/Profile27/Scores.json`.
- `Menu.cs`: 기존 커스터마이징 Button.onClick으로 24종을 선택하고 프레임·애니메이션·모자를 확인했다. 프로필 비활성화 중 결과 이벤트를 전달한 뒤 실제 MainMenu 씬을 재로드해 점수와 스킨 유지, 로그인 후 연결, 다음 결과 반영, 로그아웃 초기화를 확인했다. 160개 검사 통과. 증거는 `Logs/Profile27/Menu.json`.
- 별도 익명 프로필에서 UGS 점수를 읽기만 했다. 검사 전후 모두 랭킹 항목 없음이며 실제 점수 지급·경기 보고 요청은 보내지 않았다. 경기 결과는 이벤트에 주입한 검사용 값이다. 실제 랭킹 경기 전체의 점수 지급 검증은 아니다.
- `male_mort.png`, `female_vita.png`, `Leaderboard.png`에서 실제 Play 화면을 확인했다. 테스트가 바꾼 스킨 선택과 인증 프로필·로그인 상태는 복원했다.

Unity CLI의 eval_file로 Scores.cs를 실행한다. Menu.cs는 깨끗한 MainMenu에서 Play에 진입한 후 실행한다. 기존 Menu.json을 보존하기 위해 재실행은 새 로그 경로를 지정해야 한다.
