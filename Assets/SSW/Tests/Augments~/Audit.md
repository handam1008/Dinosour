# 직업 증강 연결

2026-09-26, Unity 6000.5.2f1, 프로토콜 17. Base c42b0fb 통합 후 검증.

멀티 후보는 팀원 Pool이 아닌 `NetDeck.Candidates`에서 고른다. 현재 유효 후보는 공용 30개와 직업 55개다. 직업별로 마술사 10, 마녀 10, 도박사 10, 총잡이 10, 암살자 11, 칼잡이 4개다. Deck의 기존 비활성 공용 항목 하나를 보존하여 전체 인덱스는 86개다. 기존 ID를 재정렬하지 않았다.

마녀에 빠졌던 독의 해금 82, 재생의 해금 83, 여러 포션을 해금합니다 84, 주머니 85를 추가했다. 원본 재생 카드가 독 해금 타입으로 잘못 저장되어 있어 SSW 사본의 타입만 고쳤다. 팀원 원본은 수정하지 않았다. 주머니는 기존 Shift 입력으로 교환하며 투척 전 재교환을 막는다. 서버가 포션 ID, 사용 여부, 입력 순서와 소유권을 결정하고 소유자는 승인 전 표시를 예측한다.

마녀의 추첨은 원본 AbstractPotion.weight를 직접 읽는다. 기본 목록은 피해 6, 회복 3, 둔화 2, 속도 2이며 해금 시 독 1.5와 재생 1.5가 추가된다. 각 가중치는 당시 후보의 가중치 합으로 나눈 비율이다. 사용·명중·효과를 추가로 무작위화하지 않았다. 가중치 0은 추첨에서 제외하며 총합이 0이면 만들지 않는다.

검증 기록:

- `Logs/Augments/Choices4/Checks.txt`: 실제 샌드박스 공용→직업 카드 UI, 직업 카드 55개 전체 선택·수신기 적용·리스폰 유지, 마지막 1~2개 및 모두 소진한 경우까지 616개 확인. 카드 표시의 이름·설명과 후보 ID도 확인했다. 수신기 플래그 확인이 각 증강의 모든 전투 효과를 실전 검증했다는 뜻은 아니다.
- `Logs/Augments/PocketChecks.json`, `StockChecks.json`: 포션 보관·회수·중복 사용·기한·세대 변경 17개와 기존 재고 회귀 18개 통과.
- `Logs/Boundary/WitchWeighted/PocketReplay.json`: 자동 생성 상태가 입력 ACK보다 먼저 오는 순서, 지연 교환·투척, 거절 및 오래된 ACK를 재적용하는 13개 통과.
- `Logs/Augments/Weights.json`: 가중치 구간·해금 전후 후보·원본 SO 값 변경 반영 38개 통과. 고정 입력 표본으로 알고리즘을 검사한 결과다.
- `Logs/Boundary/WitchWeighted/Checks.txt`: 실제 호스트·접속자의 보관→투척→빈손 회수, 중복 교환·발사 차단, 해금·제조 간격 연결을 확인했다. 양방향 송신 지연 100ms와 jitter 20ms를 설정했다. 같은 PC 두 프로세스 검사이며 실제 두 PC나 외부망 결과가 아니다.
- 같은 실행의 `Natural.json`은 난수나 제조 시각을 주입하지 않은 8초 동안의 실제 제조 기록이다. 표본이 작으므로 분포가 확률과 일치한다는 통계 검증으로 사용하지 않는다.
- 비어 있던 NetPlayer._guard를 같은 프리팹의 기존 BuffGuard에 연결했다. 양쪽 실제 방어 입력에서 피해 차단, 쿨타임 중 재사용 차단, 종료 후 피해 재개를 확인했다.

아이콘 원본이 없는 카드는 기존 대체 그림을 유지한다. 증강 획득 UI와 직업 프리뷰 모자 배치는 별도 담당 변경을 보존한다.
