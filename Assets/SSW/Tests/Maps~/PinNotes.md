# 고정핀과 경계 검증

2026-09-27, Unity 6000.5.2f1, 네트워크 프로토콜 20.

네트워크 공격의 지형 검사에서 트리거인 고정핀이 빠져 있었다. MapCombat이 살아 있는 핀과 실제 지형 중 가까운 충돌을 선택한다. 총알·도박사 투사체·마술사 카드·피해 포션과 칼잡이·암살자 근접 공격이 기존 Pin 피해 경로를 사용한다. 근접 공격은 벽 너머의 핀을 자르지 않는다.

관통 투사체는 같은 핀을 다시 처리하지 않고 남은 이동 구간을 끝까지 진행한다. 접속자의 예측 표시도 관통 여부를 사용하므로 피해가 0이어서 핀이 살아 있어도 그 자리에 멈추지 않는다. 돌아오는 카드는 지형을 통과하면서 핀 판정은 유지한다.

Base의 eb63bca까지 병합했다. 팀원이 조정한 네트워크 맵 경계 수치와 칼잡이 수치를 보존했다. 맵 자동 갱신은 기존 Collider에 설정된 MapEdges의 피해·반발을 유지하며, 새 경계만 원본 수치로 초기화한다. 기존 경계 밸런스는 Assets/SSW/Maps/Battle의 MapEdges에서 편집한다. Map16에 남은 삭제된 컴포넌트 참조 1개도 정리했다. 마지막 원본 변경에서도 피해 5·반발 20을 확인했으며, 이전 자동 갱신 값이 다시 포함된 Map01·02·03·08·14는 연결된 에디터에서 해당 원본 수치로 맞췄다. 근거는 `Logs/Swing/SourceEdgesFinal.json`이다.

## 완료한 검사

- `Logs/Boundary/MaterialsLatest/Result.json`: 모든 6개 직업의 호스트·접속자에서 Rigidbody2D와 활성 Collider2D의 Player Physics 연결 등 54개 통과. 이후 이 연결을 바꾸는 변경은 없다.
- `Logs/Swing/CombatCheck.json`: 핀 포함 맵 6개에서 원형·캡슐 충돌, 가까운 지형 우선, 근접 시야, 살아 있는 핀의 예측 정지, 돌아오는 카드의 지형 제외, 피해 0 관통, 파괴 후 정지 해제 등 115개 통과. 돌아오는 카드의 항목은 물리 질의 검사이며 증강을 장착한 실제 귀환 비행 전체를 검증한 것은 아니다.
- `Logs/Boundary/MapAttacks/CombatCases.json`의 총잡이·도박사 4개 입력 사례와 `MapAttacksLatest/CombatCases.json`의 마술사 2개 입력 사례: 두 소유자의 실제 공격으로 핀·줄 제거를 양쪽에서 확인했다. 이 실행들의 뒤 단계는 준비 코드 오류로 중단됐으므로 전체 실행 성공으로 기록하지 않는다.
- `Logs/Boundary/MapAttacksRemaining/CombatResult.json`: 마녀·칼잡이·암살자 평타, 암살자 투척칼, 피해 0 투척칼의 양쪽 소유자 입력으로 22개 통과. 투척칼은 양쪽에서 핀 너머에 도달했고, 피해 0이면 핀이 그대로 살아 있었다. 앞선 네 직업 입력 사례와 합쳐 공격 관련 확인은 34개다.
- `SwingNativeFixed/Checks.txt`의 Map16·Map17 12개와 `SwingLatestMaps/Checks.txt`의 Map01·Map08·Map12 24개: 각 맵에서 호스트와 접속자가 직접 착지하고 걸을 때 매달린 발판이 움직였다. 후자의 두 화면 위치 허용 차이는 0.35이며 원본 질량 50인 발판도 유지했다. 해당 실행들의 후속 실패를 전체 통과로 간주하지 않는다.
- `Logs/Boundary/SwingCutOpen/Checks.txt`: 총잡이 양쪽 입력으로 핀 절단·발판 낙하 후 실제 사망을 두 번 발생시켜 새 맵·플레이어 생성, 이전 개체 제거, 핀·줄·발판 복구 16개 통과. 복구를 비교하기 위해 다음 맵 번호만 같은 맵으로 지정했고 라운드 종료와 재스폰은 실제 경로를 사용했다.
- `Logs/Swing/BakeCheck.json`: 대상 11개 맵을 강제로 다시 생성한 뒤 전체 17개 맵의 경계 68개가 원래 튜닝을 유지했다. 두 번째 갱신에서는 변경이 없었다.
- `Logs/Swing/MapBindingsFinal.json`: 최신 17개 맵의 스폰·물리·서버 참조 234개 통과.
- `Logs/Boundary/EdgesFinalChecked/EdgesMotion.json`: 새 경계 수치를 쓰는 16개 맵에서 좌우 벽 × 이동·대쉬의 64개 경우를 통과했다. 두 소유자가 바깥 방향 입력을 유지하는 동안 피해와 안쪽 반발을 양쪽 실행본에서 관측했다. 마지막 원본 병합 후에도 이 검사의 경계 수치·충돌 배치를 유지한다. 변경되지 않은 SwingMap은 앞선 `EdgesHeld2`의 근거를 유지한다.

공격 검사는 한 PC의 에디터 호스트와 별도 개발 실행본을 사용했다. 양방향 전송에 지연 60ms와 지터 10ms를 설정했다. 실제 두 PC·Relay 검사가 아니다. 공격을 정렬할 때만 메모리에 복제한 직업 설정의 플레이어 중력을 0으로 두었고, 투사체 물리와 맵 배치는 유지했다. 피해 0 사례는 복제한 암살자 스킬 피해만 추가로 0으로 설정했다.

초기 핀 타격 시도는 Map16 중앙 장애물 또는 SwingMap 천장에 막혔으므로 핀 버그의 단독 재현 근거로 쓰지 않는다. 이후 실제 맵에서 막히지 않는 핀을 찾아 원래 공격을 사용했다. 마녀 준비 코드의 인벤토리 세대 불일치 반복은 검사 코드에서 제거했다. 그때의 임시 씬 백업은 `Logs/Integration/PinTestSceneBackup`에 보존했다. 최신 경계 첫 시도의 호스트 이동 입력이 0으로 생성된 문제도 검사 준비 코드에서 수정했다. 갱신 중인 진단 JSON을 읽으며 여러 스냅샷이 섞이는 준비 오류는 단일 파일 읽기와 파싱 결과 검사로 제거한 뒤 64개를 재실행했다.

재실행은 `Hazards.ps1 -CombatOnly -CombatJobs @('Gunner','Gambler','Magician','Witch','Swordsman','Assassin','Knife','KnifeZero')`, `-SwingOnly`, `-EdgeMotion`을 사용하며 매번 다른 `-Run`을 지정한다. `CombatCheck.cs`, `BakeCheck.cs`, `RefreshCheck.cs`는 플레이가 종료된 에디터에서 Unity CLI의 eval_file로 실행한다.
